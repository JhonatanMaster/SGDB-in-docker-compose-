Docker Compose + MySQL

Suba um banco MySQL com dados persistentes, acessível pelo terminal e pelo DBeaver. Inclui importação de arquivos .sql.

1

Pré-requisitos

  • Docker — motor que roda os containers
  • Docker Compose — orquestra containers via YAML (já vem no Docker Desktop)
terminal 
docker --version
docker compose version
2

Criar a pasta do projeto

terminal 
mkdir meu-mysql && cd meu-mysql
3

Criar o docker-compose.yml

docker-compose.yml 
version: "3.8"

services:
  mysql:
    # Imagem oficial do MySQL (versão 8)
    image: mysql:8

    # Nome fixo do container
    container_name: meu_mysql

    # Reinicia sozinho se o Docker reiniciar
    restart: unless-stopped

    environment:
      # Senha do root (obrigatória)
      MYSQL_ROOT_PASSWORD: root_senha_123
      # Banco criado automaticamente ao iniciar
      MYSQL_DATABASE: meu_banco
      # Usuário extra (acessa só o MYSQL_DATABASE)
      MYSQL_USER: admin
      MYSQL_PASSWORD: admin_senha_123

    # Porta: host:container (3306 = padrão MySQL)
    ports:
      - "3306:3306"

    # Volume para persistência dos dados
    volumes:
      - mysqldata:/var/lib/mysql

# Volume nomeado = dados sobrevivem ao docker compose down
volumes:
  mysqldata:
Por que o volume? Sem ele, os dados ficam dentro do container e morrem com docker compose down. O volume nomeado mysqldata guarda tudo num local separado.

Dois usuários

root = superusuário total. admin = acessa só o banco definido em MYSQL_DATABASE.

vs PostgreSQL

Pasta de dados: /var/lib/mysql (Postgres usa /var/lib/postgresql/data). Porta padrão: 3306 (Postgres usa 5432).

4

Subir o container

terminal 
# -d = roda em segundo plano
docker compose up -d

# Confirma se está rodando
docker ps

O MySQL pode levar 10-20 segundos para inicializar na primeira vez.

5

Acessar pelo Terminal

Com o usuário admin 
# -u = usuário | -p (colado na senha, sem espaço!)
docker exec -it meu_mysql \
  mysql -u admin -padmin_senha_123 meu_banco
Com o usuário root 
# Root tem acesso total a todos os bancos
docker exec -it meu_mysql \
  mysql -u root -proot_senha_123
Por que -p colado na senha? No MySQL, -padmin_senha_123 (sem espaço) passa a senha direto. Com espaço (-p admin_senha_123) ele interpreta "admin_senha_123" como nome do banco. O aviso "Using a password on the command line interface can be insecure" é normal — pode ignorar no desenvolvimento.
ComandoO que faz
SHOW DATABASES;Lista todos os bancos
USE meu_banco;Seleciona um banco
SHOW TABLES;Lista tabelas do banco atual
DESCRIBE tabela;Estrutura de uma tabela
exitSai do mysql

7

Importar arquivo .sql

Para importar um .sql (criar tabelas, popular dados, restaurar backup), envie o conteúdo do arquivo para o mysql dentro do container. O comando muda entre Windows e Linux:

Windows (PowerShell)
Linux / Mac
PowerShell 
# Get-Content lê o arquivo .sql
# O | (pipe) envia o conteúdo para o mysql
# -i = aceita entrada via pipe (NÃO use -it aqui!)

Get-Content .\empresa.sql | docker exec -i meu_mysql mysql -u root -proot_senha_123 meu_banco

# Verificar se as tabelas foram criadas:
docker exec -it meu_mysql mysql -u root -proot_senha_123 meu_banco -e "SHOW TABLES;"
Encoding UTF-8 Se der erro com acentos, force UTF-8:
Get-Content .\empresa.sql -Encoding UTF8 | docker exec -i ...
Linux / Mac 
# O < redireciona o conteúdo do arquivo
# para o stdin do mysql dentro do container
# -i = aceita entrada via pipe (NÃO use -it aqui!)

docker exec -i meu_mysql mysql -u root -proot_senha_123 meu_banco < empresa.sql

# Verificar se as tabelas foram criadas:
docker exec -it meu_mysql mysql -u root -proot_senha_123 meu_banco -e "SHOW TABLES;"
-i vs -it na importação Na importação use -i (sem o t). O -t aloca um terminal interativo, que conflita com o redirecionamento do arquivo. Use -it só quando for digitar comandos manualmente.

Método alternativo — copiar o arquivo para dentro do container:

Funciona em qualquer SO 
# 1. Copia o .sql para dentro do container
docker cp empresa.sql meu_mysql:/tmp/empresa.sql

# 2. Executa o arquivo de dentro do container
docker exec -it meu_mysql \
  mysql -u root -proot_senha_123 meu_banco -e "SOURCE /tmp/empresa.sql"
docker cp é universal! Se o pipe der problema no PowerShell, use docker cp + SOURCE. Funciona igual em Windows, Linux e Mac.

Importar para um banco que ainda não existe:

Criar banco + importar 
# 1. Cria o banco primeiro
docker exec -it meu_mysql \
  mysql -u root -proot_senha_123 -e "CREATE DATABASE empresa;"

# 2. Importa o .sql para o novo banco (PowerShell)
Get-Content .\empresa.sql | docker exec -i meu_mysql mysql -u root -proot_senha_123 empresa

# 2. Importa o .sql para o novo banco (Linux/Mac)
docker exec -i meu_mysql mysql -u root -proot_senha_123 empresa < empresa.sql
8

Testar a persistência

terminal 
# 1. Cria tabela e insere dado
docker exec -it meu_mysql \
  mysql -u admin -padmin_senha_123 meu_banco -e "
    CREATE TABLE teste (id INT AUTO_INCREMENT PRIMARY KEY, nome VARCHAR(100));
    INSERT INTO teste (nome) VALUES ('Docker funciona!');
  "

# 2. Derruba e remove o container
docker compose down

# 3. Sobe novamente
docker compose up -d

# 4. Dados continuam lá!
docker exec -it meu_mysql \
  mysql -u admin -padmin_senha_123 meu_banco -e "SELECT * FROM teste;"

Comandos do dia a dia

AçãoComando
Subirdocker compose up -d
Parar (mantém container)docker compose stop
Parar e remover containerdocker compose down
Ver logsdocker compose logs -f
Exportar banco (backup)docker exec meu_mysql mysqldump -u root -proot_senha_123 meu_banco > backup.sql
Remover TUDO (inclusive dados)docker compose down -v
Cuidado com o -v O docker compose down -v apaga os volumes e deleta todos os seus dados permanentemente!
