Docker Compose + PostgreSQL

Suba um banco Postgres com dados persistentes, acessível pelo terminal e pelo DBeaver. Inclui importação de arquivos .sql.

1

Pré-requisitos

  • Docker — motor que roda os containers
  • Docker Compose — orquestra containers via YAML (já vem no Docker Desktop)
terminal 
docker --version
docker compose version
2

Criar a pasta do projeto

terminal 
mkdir meu-postgres && cd meu-postgres
3

Criar o docker-compose.yml

docker-compose.yml 
version: "3.8"

services:
  postgres:
    # Imagem oficial do PostgreSQL (versão 16)
    image: postgres:16

    # Nome fixo do container
    container_name: meu_postgres

    # Reinicia sozinho se o Docker reiniciar
    restart: unless-stopped

    environment:
      # Senha do superusuário "postgres"
      POSTGRES_PASSWORD: minha_senha_123
      # Banco criado automaticamente ao iniciar
      POSTGRES_DB: meu_banco
      POSTGRES_USER: postgres

    # Porta: host:container (5432 = padrão Postgres)
    ports:
      - "5432:5432"

    # Volume para persistência dos dados
    volumes:
      - pgdata:/var/lib/postgresql/data

# Volume nomeado = dados sobrevivem ao docker compose down
volumes:
  pgdata:
Por que o volume? Sem ele, os dados ficam dentro do container e morrem com docker compose down. O volume nomeado pgdata guarda tudo num local separado.
4

Subir o container

terminal 
# -d = roda em segundo plano
docker compose up -d

# Confirma se está rodando
docker ps
5

Acessar pelo Terminal

Opção A — entrar no container 
docker exec -it meu_postgres bash

# Dentro do container:
psql -U postgres -d meu_banco
Opção B — direto com psql 
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco
Comando psqlO que faz
\lLista todos os bancos
\dtLista tabelas do banco atual
\d tabelaEstrutura de uma tabela
\qSai do psql

7

Importar arquivo .sql

Para importar um arquivo .sql (criar tabelas, inserir dados, restaurar backup), o processo é enviar o conteúdo do arquivo para o psql dentro do container. O comando muda entre Windows e Linux:

Windows (PowerShell)
Linux / Mac
PowerShell 
# Get-Content lê o arquivo e o | (pipe) envia
# o conteúdo para o psql dentro do container
# -i = modo interativo (aceita entrada via pipe)

Get-Content .\empresa.sql | docker exec -i meu_postgres psql -U postgres -d meu_banco

# Verificar se as tabelas foram criadas:
docker exec -it meu_postgres psql -U postgres -d meu_banco -c "\dt"
Atenção ao encoding! Se o .sql tiver caracteres especiais (acentos) e der erro, force UTF-8:
Get-Content .\empresa.sql -Encoding UTF8 | docker exec -i ...
Linux / Mac 
# O operador < redireciona o conteúdo do arquivo
# para o stdin do psql dentro do container
# -i = modo interativo (aceita entrada via pipe)

docker exec -i meu_postgres psql -U postgres -d meu_banco < empresa.sql

# Verificar se as tabelas foram criadas:
docker exec -it meu_postgres psql -U postgres -d meu_banco -c "\dt"

Método alternativo — copiar o arquivo para dentro do container primeiro:

Funciona em qualquer SO 
# 1. Copia o .sql para dentro do container
docker cp empresa.sql meu_postgres:/tmp/empresa.sql

# 2. Executa o arquivo de dentro do container
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco -f /tmp/empresa.sql
docker cp funciona em qualquer sistema! Se o pipe der problema no PowerShell, use docker cp + psql -f. É o método mais universal.
8

Testar a persistência

terminal 
# 1. Cria tabela e insere dado
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco -c "
    CREATE TABLE teste (id SERIAL, nome TEXT);
    INSERT INTO teste (nome) VALUES ('Docker funciona!');
  "

# 2. Derruba e remove o container
docker compose down

# 3. Sobe novamente
docker compose up -d

# 4. Dados continuam lá!
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco -c "SELECT * FROM teste;"

AçãoComando
