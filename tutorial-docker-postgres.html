Docker Compose + PostgreSQL

Suba um banco Postgres com dados persistentes, acessível pelo terminal e pelo DBeaver.

1

Pré-requisitos

Você precisa ter instalado:

  • Docker — o motor que roda os containers
  • Docker Compose — orquestra containers via arquivo YAML (já vem junto no Docker Desktop)

Verifique se está tudo certo:

terminal 
docker --version
docker compose version
2

Criar a pasta do projeto

Crie uma pasta onde ficará o arquivo de configuração:

terminal 
# Cria a pasta e entra nela
mkdir meu-postgres && cd meu-postgres
3

Criar o docker-compose.yml

Este é o arquivo principal. Cada linha está comentada:

docker-compose.yml 
# Versão da sintaxe do Compose
version: "3.8"

services:
  postgres:
    # Imagem oficial do PostgreSQL (versão 16)
    image: postgres:16

    # Nome fixo do container (facilita achar)
    container_name: meu_postgres

    # Reinicia sozinho se o Docker reiniciar
    restart: unless-stopped

    # Variáveis de ambiente (configuram o banco)
    environment:
      # Senha do superusuário "postgres"
      POSTGRES_PASSWORD: minha_senha_123

      # Cria um banco automaticamente ao iniciar
      POSTGRES_DB: meu_banco

      # (Opcional) Criar outro usuário além do "postgres"
      POSTGRES_USER: postgres

    # Mapeia a porta do container para a máquina
    # formato: "porta_host:porta_container"
    # 5432 é a porta padrão do PostgreSQL
    ports:
      - "5432:5432"

    # VOLUME: onde os dados ficam salvos!
    # Mapeia a pasta de dados do Postgres para
    # um volume Docker que NÃO é apagado ao
    # remover o container
    volumes:
      - pgdata:/var/lib/postgresql/data

# Declara o volume nomeado
# É isso que garante a persistência dos dados!
volumes:
  pgdata:
Por que o volume? Sem o volume, os dados ficam dentro do container. Se você fizer docker compose down, o container é removido e os dados vão junto. Com o volume nomeado pgdata, os dados ficam num local separado gerenciado pelo Docker.
4

Subir o container

terminal 
# -d = roda em segundo plano (detached)
docker compose up -d

# Veja se está rodando
docker ps

Você verá o container meu_postgres com status Up.

5

Acessar pelo Terminal

Existem duas formas:

Opção A — entrar no container 
# Abre um terminal dentro do container
docker exec -it meu_postgres bash

# Já dentro do container, conecta no banco
psql -U postgres -d meu_banco
Opção B — direto com psql 
# Executa o psql direto sem abrir bash
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco

Comandos úteis dentro do psql:

ComandoO que faz
\lLista todos os bancos
\dtLista tabelas do banco atual
\d tabelaMostra estrutura de uma tabela
\qSai do psql
6

Acessar pelo DBeaver

Abra o DBeaver e crie uma nova conexão PostgreSQL com:

CampoValor
Hostlocalhost
Porta5432
Databasemeu_banco
Usuáriopostgres
Senhaminha_senha_123

Clique em Test Connection para validar, depois Finish.

Porta ocupada? Se a 5432 já estiver em uso (outro Postgres instalado), mude o mapeamento no docker-compose.yml para "5433:5432" e use a porta 5433 no DBeaver.
7

Testar a persistência

Vamos criar dados, derrubar o container e verificar que nada se perdeu:

terminal 
# 1. Conecta e cria uma tabela com dados
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco -c "
    CREATE TABLE teste (id SERIAL, nome TEXT);
    INSERT INTO teste (nome) VALUES ('Docker funciona!');
  "

# 2. Derruba e REMOVE o container
docker compose down

# 3. Sobe novamente
docker compose up -d

# 4. Verifica se os dados continuam lá
docker exec -it meu_postgres \
  psql -U postgres -d meu_banco -c "SELECT * FROM teste;"

# Resultado esperado:
#  id |       nome
# ----+------------------
#   1 | Docker funciona!
8

Comandos do dia a dia

AçãoComando
Subirdocker compose up -d
Parar (mantém container)docker compose stop
Parar e remover containerdocker compose down
Ver logsdocker compose logs -f
Remover TUDO (inclusive dados)docker compose down -v
Cuidado com o -v O docker compose down -v apaga os volumes. Isso deleta todos os seus dados permanentemente!
